# GRPO run3 配置与决策记录

日期：2026-10-01

配置文件：[configs/grpo_run3.yaml](../../configs/grpo_run3.yaml)

## 训练目标

run3 从相同的 SFT 合并模型开始，继续使用 ShopSimulator Environment v2.1、Reward v3、observation v2 和 tool schema v2。当前任务只改变 GRPO 优化配置，Reward v4 仍处于离线校准阶段，避免把奖励实现变化与优化器变化同时引入正式训练。

## 冻结配置

| 项目 | run3 取值 | 选择理由 |
|---|---:|---|
| 任务组数量 | 32 | 提高独立任务覆盖，减小任务难度造成的批次波动 |
| 每组轨迹数量 | 8 | 保留已有组内采样经验，困难任务更容易出现可比较结果 |
| 每次训练轨迹数量 | 256 | 32 组乘以 8 条轨迹，增加独立任务带来的梯度稳定性 |
| `ppo_epochs` | 1 | 每批新轨迹只使用一轮，减少终局评分噪声和旧数据偏移 |
| 学习率 | `5e-7` | 位于 run1 的 `1e-6` 与 run2 的 `2e-7` 之间 |
| 学习率调度 | 8 次预热后 cosine 衰减，`min_lr_ratio=0.4`，`num_cycles=0.5` | 保留后段减小更新尺度的能力，终点学习率仍有足够幅度 |
| actor KL | 开启，系数 `0.003` | 保留 SFT reference 的轻量约束，降低全参累计漂移 |
| KL 类型 | `low_var_kl` | 延续 run2 的数值稳定实现 |
| 组内标准差归一化 | 关闭 | 使用 `R_i - mean(R_g)`，不放大评分噪声小分差 |
| 动态采样 | 开启 | 过滤组内奖励完全相同的组，并补采有效组 |
| PPO 下界与上界 | `0.2 / 0.2` | 当前每批只更新一次，保留对称裁剪基线 |
| Loss 聚合 | `token-mean` | 以全局有效 assistant token 数归一化，避免逐轨迹长度除法 |
| Rollout IS | token 级，阈值 `2.0` | 延续 run2 的 rollout 与训练概率差修正 |
| 熵系数 | `0.0` | 记录熵变化，暂时不叠加额外探索目标 |
| 最大响应长度 | `20480` | 覆盖当前长轨迹分布，保持 24K 总序列预算 |
| 总更新次数 | 125 | 与 run1、run2 保持可比的更新次数 |

veRL 0.9.1 会将 `ppo_mini_batch_size=32` 乘以 `n=8`，得到 256 条轨迹的全局 mini-batch。`ppo_micro_batch_size_per_gpu=1` 配合固定微批次模式限制单次显存占用，依靠梯度累积完成一次全局更新；rollout 和 reference 的 log probability 计算也固定使用每张 GPU 一个样本。

`train_batch_size=32` 与动态采样一起使用时，补采数量会增加。训练数据有 1,000 个任务，配置使用 `total_epochs=10`，为 125 次更新和动态补采保留数据余量。环境服务使用至少 256 个会话容量，配置使用单个补采批次在飞；启动前按不超过 256 个活跃会话规划，并检查实际占用。

## 训练信号

优势使用：

```text
A_i = R_i - mean(R_g)
```

所有轨迹仍然把同一个终局优势分配给该轨迹的 assistant token。`token-mean` 只改变不同长度轨迹在损失中的权重，不能提供步骤级信用分配。搜索、规格选择和购买动作仍然需要依靠终局结果学习。

当前配置保留 Reward v3 的终局奖励和 JEV 灰区处理。Reward v3 的 `weighted_score`、JEV 提升分数和 `reward_valid` 必须以实际写入 `output.reward_score` 的值统计，环境 `reward_detail` 与最终训练分数分开保存。

## run3 观察项目

每个检查点需要同时记录以下指标：

- 冻结开发集上的严格 `gold_purchase` 完成率；
- 真实完成率、替代购买率、错误购买率、循环终止率和截断率；
- 组内零方差比例、组内奖励标准差、优势绝对值均值和优势均方根；
- 熵、reference KL、PPO 裁剪比例、rollout IS 有效样本量；
- 平均轨迹长度、长轨迹失败率、teacher_hard 任务占比；
- 动态采样过滤前后的任务难度、领域和画像条件分布。

## run2 JEV 补充评测

run2 step40 的 1,092 道完整评测已经完成 JEV 灰区判定。严格完成率为
`659/1092 = 60.35%`；JEV 语义口径下，可评分任务为 1,050，完成任务为
753，真实完成率为 `71.71%`。

JEV 结果包含 94 条 `fully_satisfies` 替代购买、115 条
`partially_satisfies`、26 条 `does_not_satisfy` 和 2 条
`insufficient_evidence`。无效任务 42 条，其中 38 条为
`reward_unverifiable`、2 条为基础设施错误、2 条为证据不足。

与 run1 的 JEV 结果相比，严格完成率从 57.42% 提高到 60.35%，真实完成率从
70.34% 提高到 71.71%。run2 的真实完成率仍略低于 SFT 记录的 72.1%，因此当前
证据说明 run2 恢复了 SFT 水平并改善了稳定性，尚未证明 GRPO 已经超过 SFT。

详细结果保存在 `outputs/evaluation/grpo-run2-step40/jev_summary.json`、
`jev_task_results.jsonl` 和 `jev_verdicts.jsonl`。

模型选择使用冻结开发集严格完成率和逐题变化。完整 V2 正式评测只接受 `reward_valid=true` 的 `gold_purchase`，run3 训练与开发集结果不能替代正式评测。
