# Final-200 Clean 评测集

Final-200 Clean 是本仓库唯一用于横向比较的正式测试集。它仍有 200 题，但不是原始
Final-200 的原封不动副本：剔除了 81 道会让 Reward v3 错判、漏判或无法达到严格成功的
原题，再从冻结的 ShopSimulator 任务池补入 81 道已经过相同检查的任务。

| 项目 | 值 |
|---|---|
| 任务清单 | `data/evaluation/tasks.jsonl` |
| 任务数 | 200 |
| 环境 / Reward | ShopSimulator v2.1 / Reward v3 |
| SHA-256 | `d99112a20ef47534c27a32e4b38229bf048dcc6b06fef2e3e919aac3093662f5` |
| 防泄漏 ID 清单 | `src/shopping_grpo/resources/blind_final_task_ids.json` |
| 更新与轨迹审计 | [evaluation-updates.md](evaluation-updates.md) |

评测入口不变：`bash scripts/evaluate.sh NAME`。原始 Final-200 和中间版 Final-183 的
结果均为历史结果，不能与本集新 rollout 直接并列。

## 保留标准

每道题必须同时满足以下条件：目标商品按 gold 规格购买时得到 `gold_purchase`；gold 规格
能唯一落在真实规格轴上；最终 variant 价格可由 Reward v3 确定；Query 一旦表达价格，
解析器也必须实际得到预算上限；并且 task ID 与当前 SFT、pure-SFT、GRPO 数据零重叠。

这是一个很实用的“评分可达且评分覆盖需求”的门槛：它消除了已知的错题和漏判，但不声称
已经证明每一道题的所有合理替代商品都会得到同样高分。

## 维护规则

后续改动必须先追加 [evaluation-updates.md](evaluation-updates.md)，再同步任务清单、metadata
和 packaged blind guard；随后运行 `tests/test_evaluation_dataset.py`，确认数量、哈希和 ID
防泄漏清单一致。历史轨迹可以按新 ID 集重算分母，但不得把重算说成重新 rollout。
