# 面向长程购物 Agent 的 RL 后训练（二）：从 2B LoRA 到 9B 全参

项目地址：https://github.com/YYHDBL/shopping-grpo-longhorizon

上一篇：[面向长程购物 Agent 的 RL 后训练](/)

## 一、为什么会有 V2

V1 跑完之后 我给自己记了三笔账：

第一笔 数据太少。SFT 教材只有 428 条轨迹。模型学到的大概是"购物流程长什么样" 而不是"各种各样的需求怎么处理"。想靠几百条数据把一个模型教到能处理真实的长尾需求 我现在觉得不现实。

第二笔 模型太小。Qwen3.5-2B + LoRA 上限摆在那。当时选 2B 是算力账算出来的 没毛病 但我一直想知道 往上走一级 会发生什么。

第三笔 GRPO 的收益存疑。+1.5 个百分点的严格成功率 单次 rollout 没有方差 我自己都不信。RL 到底在这个任务上有没有用 这个问题 V1 没回答出来。

正好组里能腾出 4 张 A800-80GB。于是 V2 的目标很直接：把这三笔账全还了。模型换成 Qwen3.5-9B 全参 BF16 FSDP 数据从几百条堆到几千条 RL 那笔账 前前后后用四轮完整的训练去还（两次失败 一次成功 一次方向错误的实验——失败的部分和成功的部分一样值得写）。

先说最终结论免得你白读（全部是 1092 题冻结评测集的贪婪解码结果。严格口径 = 真买到目标商品才算 真实口径 = 加上被判定模型认可的优质替代品）：

```text
Base（9B 零样本）       严格 39.0%   真实 52.8%
SFT（起点）             严格 60.7%   真实 72.1%
GRPO run1（熵爆炸中止）  严格 57.4%   真实 70.3%
GRPO run2（太保守）      严格 60.3%   真实 71.7%
GRPO run3（最优）        严格 61.4%   真实 74.1%
GRPO run4（reward 实验） 严格 61.3%   真实 74.0%
```

SFT 的提升和 V1 一个量级 这个不意外。真正值得写的是后面：一次把 RL 做砸的完整复盘、一次把它救回来的调参、一次想再进一步但找错了方向的实验、以及**用轨迹对比分析回答"RL 到底改变了模型的什么行为"**——最后这个我认为是整个 V2 最有意思的部分。

## 二、先把数据地基重打了

### 2.1 这次源头数据大了两个数量级

V1 是 604 个任务。V2 直接从源数据池里拿：23,421 条任务级记录。

量一大 第一个问题就不是"怎么用"而是"哪些能用"。之前 428 条我肉眼加规则就能过一遍 现在两万多条 必须有一套能规模化 又能控制质量的验收管线。做法是 V1 三段式的加强版：代码规则先过 再用一个专门的判定模型过 最后抽样复核。

### 2.2 Jev：一个便宜的专用判定模型

中间那层不是随便叫一个 LLM 来当裁判 而是一个专用判定模型(decisions 接口) 输出结构化的判定(fully / partially / does not satisfy / insufficient evidence) 不是自由发挥的散文。跑两万次调用大概 0.7 美金 跟让它干的事情比约等于免费。

**但是**——Jev 不是引入就能直接信的。我先用它全量跑了 22,467 次判定 把数据分成接受/拒绝 然后随机抽了一批"被拒"的 找了六个互相独立的盲判去复核。结果发现 Jev 偏严：

- "40 元左右"买了个 42 元的 Jev 判不满足——但站在真实用户角度 42 就是"左右"
- "礼盒装"和"含礼盒"这种同义表述偶尔判不匹配

复核把 2,475 条从"拒绝"里救了回来。

> **🌟**
> LLM 裁判引入之后 先校准 再全量 再冻结。
> 直接信任何一个裁判(包括人)都会把标尺本身变成噪声源。

最终 23,421 条里筛出 accepted 19,106 条（81.5%）。

### 2.3 画像：这次真的做了

ShopSimulator 论文里本来就有个性化用户画像 V1 我没做。V2 把它做进来 而且多走一步：不只是"有画像" 而是能**验证画像到底有没有用 有没有害**。

画像池 4,666 份（773 份泄漏了任务关键词的先剔除）。然后按三种条件分配：aligned（与需求一致）52%、irrelevant（无关）24%、no_profile（无画像）24%。这个三条件设计后面在评测里直接交了一份"画像效应"的答卷 第七节说。

### 2.4 一个意外发现：teacher-hard

数据重打的过程中翻出来一批题：**两个不同的 Teacher 模型 各给三次机会 都没做出来的任务 共 727 道**。

SFT 教材里没有它们的成功轨迹 也就是说模型从没被教过怎么做这种题。我单独存了一个桶 留着给 RL 去自己探索——这批题后面成了 RL 任务池里最有意思的部分。

## 三、双 Teacher 采集：分治 + 成功即停

V1 用单个 Teacher 跑全部。V2 数据量大 20 倍 改成两个 Teacher 分治：GLM-5.3-Flash 和 DeepSeek V4.1 Flash 各分一半 各 8 并发。

两个模型脾气不一样。GLM 一次通过率 90.4% 基本不用管。DeepSeek 一开始只有 44%——不是它笨 是它太"谨慎" 总在核验细节上绕圈。给了它一版收敛性提示词（确认关键约束后就要下手）之后提到 87.5%。

每个 Task 最多给 3 次机会 成功一条就停——不搞"刷到全对为止" 刷出来的数据是 Teacher 的上限 不是教材。

最终 6,579 个任务产出 5,852 条教材轨迹 hard 任务占 34.6% 平均 5.9 步。

### 3.1 提示词分层：Student 版和 Teacher 版

这是 V2 我自己挺得意的一个设计。

Teacher 采集时要给它完整的决策规则（什么时候该买 什么时候该停 怎么核验） 不然它做不出来题。但 SFT 训练用的 prompt 如果也带这些规则 学到的就是"读题+执行说明书" 而评测时用户不会附说明书。

所以 prompt 分两层：Teacher 版 = 协议层 + 决策规则层；Student 版 = 只有协议层。采集用 Teacher 版 教材的动作序列配上 Student 版的 prompt 进 SFT——**动作是 Teacher 的 提示词是 Student 的** prompt 移植过来 蒸馏就发生了。评测也用 Student 版 大家公平。

## 四、Harness 的三针缝补

V1 那套 Harness 的哲学（观察投影、Action Guard 当最后一道安全网）全部保留 V2 只缝了三针 都是看轨迹看出来的：

第一针 `tool_choice=required`。删掉 think 工具 删掉纯文本出口——V1 时模型偶尔会"说话"而不是"动手" 一说话这一步就废了 直接从协议上把出口焊死。

第二针 子页单次访问拦截。同一个商品详情子页看第二次 基本就是在原地打转 看过一遍的直接拦掉。

第三针 观察预算分级改成 3072/6144/1024（搜索页/详情页/普通页） 因为 9B 模型核验能力上来了 多给一点正文换来更少的误判。

另外一个 SFT 侧的重要契约：**被 Guard 拒绝的动作段落不进 Loss**（5,852 条里 941 个被拒段 训练掩码记 0）——模型不该学"怎么发出会被拒绝的动作" 也没必要因为它发过就惩罚上下文里其他正确的部分。

## 五、Reward v4：档位表、灰区升级、和我自己挖的两个坑

V1 的 reward 用了之后 暴露了三个问题：替代品一刀给 0.55 太粗（"几乎完美"和"勉强凑合"压成一个数）、档位缝隙里藏着漏洞、和环境守卫耦合的档位语义会漂移。

V2 重设计（这篇叫 **v4**）：先过两道硬门（类目、预算） 不过直接 -0.85；然后按终局分档：

```text
gold_purchase（买到目标商品）          1.00
partial（买到部分满足的替代品）         0.25
graceful_stop（充分检索后礼貌收尾）     -0.15
early_abstain（没怎么查就放弃）        -0.35
截断（预算耗尽没走到终局）             -0.50
wrong_purchase（硬门不过）             -0.85
基础设施无效                           0.00（不产生学习信号）
```

**灰区升级**：替代品那档 0.25 对"买得很好只是 ASIN 不同"的轨迹太亏。v4 让硬门通过的替代购买进入灰区判定——判定模型判 fully_satisfies 的直接升到 1.0 和 gold 同权。判定按 `(instruction, asin, options, price)` 缓存 同一组合只判一次 整个 RL 跑下来成本几美分。**Reward 里可以有 LLM 但它必须是"可缓存、可降级、标尺冻结"的** 这是我的底线设计。

### 5.1 我自己挖的坑之一：截断 0 分漏洞

v4 最初版本里 截断的轨迹记 0.0。某天对着 reward 分布看的时候发现不对：截断 0.0 比礼貌收尾 -0.15 还高——**模型拖着不结束、把预算耗光 是比"好好收尾"更优的策略**。修复：截断单独成档 -0.5 排在早退之下、买错之上。梯度方向变成：买到 > 礼貌收尾 > 早退 > 拖满预算 > 买错。

### 5.2 我自己挖的坑之二：连续长度惩罚 加了又撤

第二个坑更微妙。看数据发现 SFT 模型平均跑 20 轮 同样的题 Teacher 平均 6 轮就买完了——像在过度探索。于是设计了一个软阈值的轮次惩罚（12 步内不罚 到 35 步线性拉满 上限 0.10）。

用户（就是我）把它毙了 理由很简单也很有力：**这个池子里 hard 和 teacher-hard 占了 45% 长轨迹可能包含必要的搜索、比较和规格确认 仅凭步数 无法判断哪些操作是浪费**。惩罚步数等于惩罚认真做难题的模型。

撤掉。绕了一圈回到 V1 写过的一句话——"多两步可能是无意义地重复搜索 也可能是认真核验"。区别是这次我拿着数据绕的。

> **🌟**
> 往一个结果导向的 reward 里掺过程导向的直觉 掺之前先问：
> 这个"过程偏好"有没有反例？hard 任务就是反例。

## 六、训练环境：Docker、NCCL 和三天排障

V1 租一张 RTX 6000 装完就跑。V2 换到自己的 4×A800 第一天就被上了一课。

死锁链：Qwen3.5 需要新版 vLLM → 新 vLLM 绑定 torch 2.11 → torch 2.11 只有 cu130 构建 → **服务器驱动 535 跑不了 cu130**；而能兼容驱动的旧 vLLM 不认识 Qwen3.5。宿主机上无解。

解法照抄组里其他人的做法：全在 Docker 里跑——镜像带 CUDA 兼容层 用容器用户态驱动绕开宿主机内核驱动的版本限制。

然后卡在 NCCL 上近三天：训练一启动就报 **"Duplicate GPU detected: rank 1 和 rank 0 在同一张卡上"**。各种环境变量、IPC 配置都试了没用。最后挖到的真相是：训练框架的初始化钩子里 import 了 veRL 触发了 CUDA 初始化 这一步发生在 Ray 给每个 worker 分配显卡**之前** CUDA 把"全机 8 张卡"的映射缓存住了。解法是一个环境变量 `PYTORCH_NVML_BASED_CUDA_CHECK=1` 让设备检查走 NVML 不初始化 CUDA 运行时。一行解决。

> **🌟**
> 训练容器里 每一个"顺手 import"都是在动 GPU 初始化时序。
> 非必要 不导入。（这个坑后来还复发过一次 见第九节）

## 七、SFT 与评测基准：起跑线画在哪

5,852 条教材 挖掉守卫拒绝段和参数污染的 最终 5,542 条训练 + 110 条验证。172 步 val loss 从 0.292 单调降到 0.278。9B 全参 4 卡约三个小时。

评测基准也换了：V1 的 Final-200 退役 **V2 正式评测集是冻结的 1,092 题**——和环境、SFT/GRPO 的所有训练数据严格按 task 隔离。两个口径：

- **严格完成率**：环境终局判 gold_purchase 才算
- **真实完成率**：加上灰区里被判定模型认可的优质替代品（用户视角"任务完成了吗"）

起跑线：

```text
Base（9B 零样本）  严格 39.0%   真实 52.8%
SFT                严格 60.7%   真实 72.1%
```

几个值得说的细节：

**Base 不是 0% 了。** V1 那次 Base 是 0% 因为 prompt/harness 没给 2B 模型留活路。9B 零样本能到 39% 说明大部分"交互协议"能力大模型自带 SFT 教的主要是这个环境的协议细节和决策习惯。

**画像效应的答案是负面的。** 按画像条件分桶：aligned < no_profile < irrelevant——**和需求一致的画像反而最差**。合理解释：画像给了额外的"偏好"信号 当它和当前需求有错位时 模型会被带偏。这个排序在 Base 和 SFT 上方向一致 所以不是教材的锅 是画像信号本身的副作用。

**错误形态在变。** SFT 之后剩的错误是 partial 替代 237 条、repeat_loop 68 条、顶格 35 条——比"完全不会做"难一个层级的问题 是判断力问题。这正是 RL 该出场的位置。

## 八、GRPO 第一次：熵是怎么炸的

### 8.1 配置：直接继承 V1 的判断

run1 的配置基本是 V1 的延长线：n=8、lr 1e-6 恒定、**无 KL**（连 reference 都不加载）、优势不做 std 归一化、ppo clip 0.2、1000 题（含 teacher-hard 桶）× 125 步。

无 KL 的理由 V1 写过：SFT 起点稳 用 LoRA + 小 lr + clip 兜底足够保守。V2 从 LoRA 换成全参 但 lr 还是那么小 我觉得一样保守。

**这个判断错了。而且错得很有教学意义。**

### 8.2 岔开讲：OOM 三连

训练前 3 步 OOM 了三次 才跑到正题。崩点在训练前向算 log-prob 的地方：GRPO 要逐 token 算新旧策略比值 **必须完整物化 [序列长度 × 15 万词表] 的 logits** 22k token 的轨迹就是 6.7G 一个张量 加中间量和反向 一张 80G 的卡被顶穿。

先试常规路线：全部 offload 到内存 峰值从 79G 降到 57G 过了第一步 但第二步换个重批次还是贴着天花板。

翻训练框架源码找到正解：`use_fused_kernels`——内置一个分块输出头 **512 个 token 一块 直接拿 hidden states 乘输出头权重 从头到尾不物化完整 logits** 反向逐块重算。开了之后峰值 57G → 43.8G **训练反而快了 20%**。

顺带搞明白为什么 V1 用的 liger-kernel 救不了这里：liger 最省显存的融合交叉熵是"吃 hidden states 直接吐标量 loss" 而 RL 需要每个 token 的 log_prob 拿不到中间量 所以框架源码干脆写死禁用了它。**SFT 能用的东西 RL 未必能用 这是结构性的不是配置问题。**

> **🌟**
> 说"不存在"之前 先说"我没找到"。

### 8.3 熵爆炸

OOM 修完顺利开跑。前 41 步熵在 0.36~0.48 的小带子里晃 我还挺得意。

step 45 开始爬。55 加速。75 到 1.85。87 到 **6.0**——接近均匀随机。

**step 85 之后模型产出的训练数据基本是噪声 它在用自己的噪声训练自己。** step 93 手动停了。

有意思的是验证集（贪婪解码）还稳着：step25 掉到 0.490 又回到 0.698——贪婪的 argmax 对分布变平是有抵抗力的 所以"表面还活着 内部已经在发散"。不盯熵根本看不出来。

### 8.4 为什么炸：信号一直是好的

第一反应是"没信号导致的漂移"？查了数据 不是——每步的优势极值 ±1.0~1.5 从头到尾存在 学习信号从来没断过。

信号是好的还炸 问题在"刹车"上。机制复盘成一句话：

**熵涨 → 采样更随机 → 失败率涨 → 组内分差反而更大 → 推力更强 → 熵更涨。** 一个自增强的死循环——而我把所有刹车都拆了：无 KL（没有参照物）、优势不归一化、lr 恒定（尾段不收油）。

V1 说"LoRA + 小 lr + clip 够保守"——**LoRA 本身就是一根缰绳**（可训参数不到 2%）。全参 9B 没有这根缰绳 我却以为"lr 小"能替代它。被自己的实验证伪 是 V2 最值钱的一课。

### 8.5 打捞

checkpoint 挑 step50（熵还在健康区）走完整评测：**严格 57.4% / 真实 70.3%——比 SFT 小亏 3.3pp**。错误形态很指向性：gold 少 36 条、repeat_loop 多 33 条 策略变"抖"了。发散的种子在 warmup 结束后不久就埋下了 挑 checkpoint 救不回已经发生的学习污染。

## 九、GRPO 第二次：刹车装上了，但踩得太死

run1 的病理报告直接开药方——三件刹车：

```text
KL 锚：coef 0.01（reference 全程冻结）
lr：降到 2e-7（run1 的 1/5）
batch：16 题 × 8 = 128 轨迹/步（独立任务翻倍 梯度噪声减半）
```

**KL 锚管"每步走不远" batch 管"每步方向准" lr 管"步子小"**——三个参数各管一件事。上线后有个好玩的现象：前两步 kl_loss 精确等于 0 不是 bug——warmup 期 lr 太小 权重的相对变化比 bf16 的舍入分辨率还小 一个 bit 都没动 和 reference 逐位相同。数值的诚实有时候超出直觉。

这轮还补了两件事：**动态采样**（先测出来零方差组占 47.9%——近半算力花在没学习信号的组上 然后开过滤 换新题补齐 进训练的组零方差率降到 0.0）；**仪表盘**（组级标准差、零方差率进日志，轨迹级落盘，还有 SAVE_AND_STOP——touch 一个文件 训练在下一个安全点存 checkpoint 退出 随时可停）。

中途还踩了个回旋镖：run1 修好的 NCCL Duplicate GPU **又回来了**。排查到最后是自己的锅——新加的补丁在训练钩子里 import 触发 CUDA 初始化 第六节的教训重演。修复方式是立规矩：**钩子里只留最小导入集 其余补丁全部延迟生效**。

结果呢？跑完 41 步 完整评测：

```text
run2   严格 60.3%   真实 71.7%
SFT    严格 60.7%   真实 72.1%
```

**打平。** 比 run1 好（修好了抖动） 但和 SFT 一模一样——**KL 0.01 + lr 2e-7 太保守 策略几乎没离开起点**。训练中 64 题验证分全程贴着基线下方（0.64~0.65）就是证据。

两轮下来：太松炸、太紧不动。下一步很明确——**找中间的油门**。

## 十、GRPO 第三次：从数据顺序找到的工作点

### 10.1 先发现了一个数据问题

run3 之前翻训练数据的落盘结构 发现 1000 道题是按难度**分块排列**的（medium 一块、teacher_hard 一块、easy 一块、hard 一块） 而训练框架的 dataloader **不打乱**。这意味着训练是"先连续做简答题、再连续做最难题"——整段同质、块间难度跳变。

处理方案：常规题（700 道）**混合打乱成一桶**、teacher_hard（300 道）**压轴**——课程学习：先热身再啃硬骨头。任务集一道没动 只重排行序。

### 10.2 配置：找中间

```text
lr：5e-7（run1 与 run2 之间）cosine 衰减
KL：0.003（比 run2 轻 3 倍）
batch：32 题 × 8 = 256 轨迹/步（再加一倍）
```

### 10.3 结果：第一次真正跑赢

训练中 64 题验证曲线讲了个完整故事：0.692（基线）→ 0.619（掉坑 探索的代价）→ 0.649 → 0.657 → **0.716（超越）** → 0.685（回落到基线附近）。

两个 checkpoint 的完整评测几乎一致：

```text
run3-50   严格 61.4%（670/1092）   真实 74.1%
对比 SFT：严格 +0.7pp             真实 +2.0pp
```

repeat_loop 从 SFT 的 68 条降到 51 条（所有轮次最好）。**这是四轮里唯一在两个口径上都不输 SFT 的**。

哪一步是决定性的？四个因素一起改了（lr、KL、batch、数据顺序）——说实话说不清 这就是 GRPO 调参的现实：先找到能跑的工作点 再逐个消融。

## 十一、轨迹分析：RL 到底改变了什么？

分数只告诉我"61.4% 对 60.7%"，但没告诉我**模型的行为到底哪里不一样**。SFT 和 GRPO 跑的是同一套 1092 题 天然是配对实验 逐题对比：

```text
都对 629 题  |  都错 388 题
翻盘（SFT 错 → GRPO 对）41 题
翻车（SFT 对 → GRPO 错）34 题
```

净收益 +7 题 但背后是 **75 道题的翻转**。分象限看行为指标：

**翻盘的 41 题**——SFT 的死法是"陷在循环里"：

```text
                 SFT       GRPO
平均步数         16.8 步 →  12.5 步（-25%）
重复动作          5.5 次 →  2.8 次（-48%）
```

SFT 在这类题上死磕到超时；GRPO 学会了**及时换路**。

**翻车的 34 题**——GRPO 的新死法是"过早锁定"：

```text
                 SFT       GRPO
搜索次数         2.53 次 →  2.15 次（-15%）
打开商品         2.41 个 →  2.03 个（-16%）
信息页浏览       1.24 次 →  1.82 次（+47%）
```

它看得更深但**撒网更窄**——少开了一个候选 恰好那个是对的。（我一开始猜"核验变少导致买错" 数据推翻了这个猜测：它核验得更多 问题是搜索面收窄了。）

**都对的那 629 题**：行为几乎一模一样（所有指标 ±0.1）——**RL 的主战场只在困难题上**。

把翻转题的轨迹给判定模型逐条深读（16 个样本） 模式高度一致：

> **RL 的本质改变不是"能力提升"，而是决策倾向的偏移：探索倾向降低、对当前候选的接受度提高。**

在 SFT 会陷入长循环的题上 这个偏移救命（41 题翻盘）；在 SFT 靠"多搜多核验"做对的题上 这个偏移致命（34 题翻车）。

**为什么说是自然产物**：reward 只看结果——"蒙对"和"找遍所有候选才找到"都是满分 **"探索半天最后差一点"是零分**。结果导向的训练自然会磨掉"没有回报的探索"。不是 bug 是这类 reward 的固有性质。

## 十二、Reward 实验：想治"探索不足"，它找到了第三条路

既然诊断出了"探索不足" 那就治。我设计了新 reward：**把"买错"细分**——

```text
尽力买错（探索充分后没找到）  -0.45  ← 比原来轻
草率买错（没比较就赌）        -1.00  ← 比原来重
```

"探索充分"用三个行为信号判定（打开过 ≥2 个候选、用过核验工具、用过 ≥2 个搜索词）。思路：用分数告诉模型"认真找过再失败没关系 瞎赌不行"。

从 run3-50 续训 10 步 结果：

```text
run4   严格 61.3%   真实 74.0%   ← 持平
```

买错没降、草率占比没降——目标没达成。**它实际学会的是什么**：行为数据揭晓——不是多探索 而是**第三条路**：

```text
拖到超时的（截断罚重了）    -7 条
买"部分满足"替代品的        +17 条
```

"拖下去风险大（截断 -0.65） 赶紧买个还行的（替代品 +0.25）更安全"——它把"罚截断"理解成了"别拖、快买"。轨迹深读结论更直白：**比之前更早收敛、更早下单了**——探索进一步减少 和设计意图正好相反。

教训：**"罚得狠"换不来"肯探索"**。改分数表的形状 模型总会找到设计者没设想的第三条路——这已经是这个项目的第三次（拖满预算、买替代品、下次不知道是什么）。

## 十三、TRACE 尝试：过程奖励的一盆冷水

试完 reward 层面 又去碰"过程奖励"——用细粒度信用分配奖励**每一步**。具体是 TRACE（2026 年的论文 给每个工具步骤一个"离目标更近还是更远"的分数）——它在搜索类 Agent 上有明显收益 而且不需要训 critic。

做法：用冻结参考模型给"标准答案"（该买哪件商品）打分——"当前这步之后 猜出标准答案变容易了 = 这步走对了"。先用 163 条真实轨迹做**离线验证**（不训练 纯打分） 看它打得合不合理。

发现一个机制性的坑：

```text
动作            被判定为"靠近目标"的比例
搜索                76%      ✓ 合理
看商品详情          12%      ✗ 不合理
看商品参数          3%       ✗ 严重不合理（97% 被判"走远了"）
```

**"看详情、核验参数"这些认真购物的行为 几乎全被打成负分。** 原因：详情页是一大段文字 加进上下文反而让"猜标准答案"更难——它把信息量当成了干扰。

也就是说：**这套方法天生在说"别细看 赶紧买"**——和我们最想鼓励的行为正好相反 用它训练只会加重"过早锁定"。加上成本要翻倍 到此为止。

但验证本身有价值：**任何"看答案好不好猜"类的过程奖励 在长文本场景下都要先测它惩罚了什么**；而"搜对方向"是干净的信号（76% 正判） 未来如果要设计"搜索专用"的过程奖励 有现成数据可用。

## 十四、思考

### 14.1 V1 说对的说错的

说对的：不加长度惩罚（绕一圈数据后回归）、动态过滤有价值（这次量出来 47.9%）、评测不加权成总分。

说错的：**"保守配置可以替代 KL"**——被 run1 直接证伪。LoRA 是缰绳 全参没有 缰绳必须换成 KL。

半对半错的：评测先行。V2 多了一条：**测量先于干预**——零方差率测出来之前"要不要动态采样"靠直觉吵 测出来之后是算术题。

### 14.2 RL 在这个任务上的真实边界

四轮跑完 我对"购物 Agent 的 RL 能带来什么"有了比较诚实的认识：

- **它能改的是"倾向"不是"能力"**：把"卡住时死磕"改成"卡住时换路"——收益 +2pp 真实完成率 代价是探索倾向下降
- **它改不了的是 reward 没说的东西**：你奖励什么它就优化什么 过程和动机它自己发明（第三条路）
- **调参的安全区很窄**：太松炸（run1） 太紧不动（run2） run3 的工作点是试出来的不是算出来的

### 14.3 agent 时代的工程方式

这个项目一半以上的排障（NCCL 三天、OOM 三连、熵爆炸解剖、钩子回旋镖）是我和 agent 一起完成的。我的角色从"写代码的人"变成了"提问题、定方向、拍板的人"。几次关键突破都是这个模式的产物：我给方向和怀疑 它对着源码逐条核实 把"我觉得"变成"源码第几行就是"。

纪律也学到了：agent 说"只有三条路"时 其实是"它找到三条路"——**最终拍板的人要为"没找到的那条路"负责** 所以关键结论必须要求证据链而不是结论本身。

### 14.4 教训清单（给自己）

- 说"不存在"之前说"我没找到"
- 改分组/解析逻辑前 先看真实数据落盘长什么样
- 训练钩子里非必要不 import 任何东西
- 往 reward 里掺过程偏向前 先找反例
- 罚得狠换不来肯探索——想鼓励什么 就给它正回报 而不是给反面重罚
- 任何"看答案好不好猜"类的过程信号 先测它对长文本信息的脾气
- 长训练必须有"随时可停可存"的开关
- 引入任何 LLM 裁判 先校准 再全量 再冻结

## 十五、还欠的实验

- **消融**：run3 的四个因素（lr、KL、batch、数据顺序）哪个贡献最大——没做 说不清
- **方差**：六轮对比的差异都在统计噪声边缘（1092 题 ±3pp） 单次 rollout 的债越拖越贵 多次采样是迟早要还的
- **正确的过程奖励**：TRACE 证明了"gold 可预测性"不行 正确的 proxy（以"核验后的正确判断"为目标）还没设计
- **动态采样的账**：30% 墙钟换 100% 信号 在不同训练阶段是不是都划算
- **画像**：效应是负面的（aligned 最差） 是画像质量问题还是方向不对 没查清
- **多轮对话版本**：这篇全程是单轮需求 多轮澄清和个性化场景还没碰

## 成本

- 判定模型（Jev）：数据验收 0.70 美金 + 全部灰区判定与轨迹分析若干 加起来不到 2 美金
- Teacher 采集：订阅套餐内 token（输入 4.78 亿 + 缓存 5.33 亿 + 输出 871 万）
- GPU：4×A800 自托管。四轮 GRPO 训练 + 六次 1092 题全量评测 + SFT 与基线 合计约 **200 GPU 时**
- 复盘和排障的人力：我和 agent 若干个深夜

一轮失败的 GRPO 比一轮成功的贵——因为失败之后还要再来一轮。但回头看 真正值钱的东西（轨迹分析的方法、reward shaping 的三次教训）全是从失败轮里挖出来的。

比 V1 的 50 美金贵了 纸面成本主要是 GPU。但按"每小时学到的教训"算 贬值的是我 而不是这些成本。
